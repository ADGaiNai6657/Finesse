# Finesse 新版实验趋势分析 · 2026-11-24

部分复现了论文趋势。Finesse-Gear 在四组数据上计算 SF 均快约三倍，单算法内存管线吞吐也全部提高。主要偏差仍是整体 Delta 压缩比，集中于展开源码和未压缩 tar。新版 Benchmark 和 Profiling 的算法输出一致，两种模式的压缩表示与逐块恢复证据也与旧实验一致。

## DCR 差额集中在两组的候选覆盖率

每格按 Finesse-Gear / NTransform-Gear 排列。匹配覆盖率的分母是去重后的唯一原文字节。已匹配节省率的分母是匹配目标原文字节，没有匹配时显示为不适用。DCR 为唯一原文字节除以最终 Raw 与 Delta 的合计 payload。

| 数据集 | DCR | 匹配块数 | 匹配覆盖率 | 已匹配节省率 |
| --- | --- | --- | --- | --- |
| DataSet_1 | 1.00000 / 1.00004 | 0 / 1 | 0.00% / 0.01% | — / 66.25% |
| DataSet_2 | 1.37600 / 1.65330 | 12,424 / 19,054 | 27.78% / 41.01% | 98.37% / 96.35% |
| DataSet_3 | 1.28920 / 1.54386 | 8,597 / 14,013 | 22.77% / 36.67% | 98.52% / 96.06% |
| DataSet_4 | 1.08125 / 1.13534 | 140 / 297 | 8.71% / 14.03% | 86.30% / 84.99% |

第 2、3 组中，Finesse 命中的块节省率分别高出 2.02 和 2.46 个百分点，但匹配覆盖率少了 13.23 和 13.90 个百分点，导致两组合计多存 112.7 MB，占四组字节差额的 98.4%。论文六组的 DCR 相对变化为 −3.21% 至 +7.36%。本机第 2、3 组的降幅分别为 16.77% 和 16.50%。论文 DCE 的公式和解释方向存在歧义，本表使用明确的字节节省率。

下表是每组 Delta Benchmark 的单次实跑，单位为 ms。CDC 为共享阶段。构建内已包含 SF、索引、编码及即时回放，因此同一列中的子阶段不能与构建相加。逐块恢复和文件摘要在构建结束后执行，不计入五轮单算法吞吐。

| DataSet_1 | 67.43 | 188.25 / 355.04 | 89.80 / 255.24 | — / 0.08 | — / 0.01 | 164.81 / 149.43 | 54.37 / 54.66 |

第 2 组 NTransform-Gear 的构建比 Finesse-Gear 多用 583.4 ms，其中 SF 多用 192.3 ms，Delta 编码多用 330.3 ms。编码耗时差还包含匹配次数和参与编码的字节量差异。

第 3 组 NTransform-Gear 的构建比 Finesse-Gear 多用 813.9 ms，其中 SF 多用 355.9 ms，Delta 编码多用 387.5 ms。编码耗时差还包含匹配次数和参与编码的字节量差异。
